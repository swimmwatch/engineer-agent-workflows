## Current Contract

Specification confirms scope before loading exactly the active profiles, and
writes Approved only after material answers and the gap/state checks. Planning
owns the first handoff and test-first packets. Incremental implementation
requires a usable Git worktree, executes one authorized packet, verifies it and
stops; a clean tree, commit or independent review is not a next-packet gate.

The collection has 16 explicit-only skills and separate generated client bundles.
The separate TypeScript/npm `engineer-agent-workflow-mcp` package exposes 46
scenario tools plus four compatible read-only queries. Open the absolute task
project and specification, then pass returned contexts/references. There is no
maintained allowlist or disk scan; process permissions are the access boundary.
All reads, authoring and validation of manifest, decisions, catalog and experience
YAML use scenario MCP tools. No direct YAML reader, parser or authoring fallback
is permitted. Schemas are owned under root `shared/schemas/` and packaged into
the runtime and matching dependent skills.

`design-planning` is a separate explicit stage after main planning, triggered by
manifest-declared design outputs, not merely a UI profile or existing files.
Penpot's separately installed skills/MCP own remote editing. Our workflow owns
the shared root `design/system/`, specification screen sets, local contracts,
verified snapshots and handoff. Local structural checks alone cannot establish
visual, restoration or accessibility acceptance. Independent packets need not
wait for unrelated design outputs.
