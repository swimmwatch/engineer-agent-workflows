## Schema and operation registry

The sole authored [schema family](docs/specs/testing-and-verification/contracts/schemas/data.schema.json) is Draft 7, `$id=urn:engineer-agent-workflows:testing-workspace:v1`. `protocol_version=1` is the application contract, not the negotiated MCP protocol version. Never copy business DTOs into Zod or an independent transport schema. Use the P01 **Shared data contract** selector-closure algorithm, including `$schema`, `$id`, sorted roots and transitive local `$ref` definitions, to verify these **content pins**, not managed proposal digests:

- Core wire roots `/definitions/Request`, `/definitions/Response`, `/definitions/ErrorResponse`: `25ff58433578f4dc7bb94de58254100cd7276736fc8c96d41049023fb5d73621`.
- MCP/config roots `/definitions/EmptyParams`, `/definitions/RuntimeInfoResult`, `/definitions/OperatorConfiguration`: `5ef22600c1f760404077b026977fdb3b80e8b30176f1f91d3e9b3e731bb118b1`.

Each CaseStore tool in this core registry receives the ENTIRE indicated strict `Operation_*` envelope, including its fixed `operation`, IDs-only `library`, caller-generated `request_id` and exact `params`. No automatic request ID, implicit library, coercion, dropped field or alternate default exists. The registry pairs each input with the only legal successful `Response.result`; every domain failure is exactly `ErrorResponse`.

All tools in this core registry set `idempotentHint=true`: mutations require the SAME request ID and identical canonical intent, never a newly generated retry. ## SDK framing and lifecycle

Use the existing low-level `Server` plus `serveStdio`/`StdioServerTransport` pattern from SDK server `2.0.0`; no MCP-over-HTTP proxy, mandatory daemon, browser launch or auto-registration. One explicit `testing-workspace mcp --library-grant-file <absolute-file>` process owns its server, validated startup grants and handles. MCP initialization negotiates the SDK protocol; clients subsequently inspect `testing_runtime_info`, `tools/list` names and published schemas. Host-generated namespace prefixes are never stored or hard-coded. Missing tool, wrong contract/version or unavailable verified build identity is an actionable missing prerequisite, not a raw-store fallback. No readiness call initializes/repairs data, installs a renderer or starts a scenario.

Build SDK-compatible JSON Schemas dynamically from each named common selector: materialize the selected root as an object schema, include exactly its local reference closure under `definitions`, retain Draft 7 dialect, and give generated resources distinct stable IDs. Validate these generated views against the same common validator; never maintain handwritten parallel Zod DTOs. The common core remains the authoritative business validator. Register `tools/list` and bounded `tools/call`; tool lookup and argument validation run inside the redacted error boundary. Per-operation success schema is derived from `Response` with its result narrowed to the registry's selector. SDK projection errors must not turn a committed mutation into `effect=not_applied`.

Success uses `structuredContent` plus one JSON text block containing the same value, `isError=false`. Domain/authority/limit/cancellation failures use canonical `ErrorResponse` in both surfaces with `isError=true`; SDK success projection is not applied to that error shape. Malformed MCP framing, invalid JSON-RPC or unknown tool use the SDK protocol error mechanism without echoing raw input. No stdout logs: stderr emits bounded operation/code/identity metadata only, never bodies, roots, secrets or raw validator exceptions.

Bound one stdio input frame/buffer to 2 MiB, including JSON-RPC envelope; canonical decoded request still ≤1 MiB. Core response remains ≤24 KiB; complete duplicated MCP tool result ≤64 KiB. Deterministic complete tools/list discovery is ≤4 MiB; if generated schemas exceed it, fail startup capability validation rather than omit tools or truncate schemas. Input nesting/count/scalars obey P01 (depth 32, ≤1,000,000 visits), no custom duplicate-key lexer for decoded values. Up to four admitted calls per server; excess returns BUSY without a hidden queue. Pass request cancellation to the common operation context; P02's 15-second cooperative operation deadline and 1-second SQLite lock wait remain distinct from a hard interrupt. A disconnect/timeout after possible commit preserves unknown/applied effect and exact inspect guidance; it is not rollback evidence. EOF/normal close stops admission and drains admitted operations to their bounded checkpoints, closes only this process's handles and exits; native jobs, other MCP processes and HTTP sessions remain untouched. No signal/PID-only foreign kill.

## Authority, parity and failures

The shared proposed **Adapter authority contract** in [P06](docs/specs/testing-and-verification/tasks/06_mcp-adapter.md) owns startup grants and trusted per-operation access. A stdio connection, OS-readable path, UUID, provenance reference or encoded context alone is never a project grant. There is no browser pairing requirement for agent QA through stdio; explicit operator startup configuration provides its bounded authority independently of HTTP. No request can add a root or obtain workflow-MCP decision/task authority.

All fourteen calls delegate unchanged decoded requests to the SAME `executeOperation(access, request)` core as HTTP. P01 identity/validation/byte limits, P02 compare-and-swap (CAS), retained pagination/receipt/recovery rules and P03 frozen-run/verdict rules do not fork by transport. Success acknowledges persisted effects, not truth of observations, delivery to a lost client or report readiness. After a lost reply inspect the original operation ID/digest before exact replay/recovery; never silently retry with a new ID or merge stale expectations. Reads use read-only SQLite handles and never initialize, migrate, repair or materialize a snapshot. Unknown fields/operations/version, foreign identity and unavailable capability fail explicitly.

`ErrorResponse.code` is the stable problem registry; `effect`, `acknowledgment`, `next_action` and bounded `issues` retain their common meaning. At most 20 safe field/record issue samples; messages ≤500 scalars, full response ≤24 KiB. Do not expose absolute paths, SQL, source values or session/config secrets, including on SDK/serialization/internal errors. Failure before core admission reports `effect=not_applied`; uncertainty after admission is not denied merely because delivery failed.

## Navigation operation registry

NEW P06 shared application `executeNavigation(access,request)` supplies required public run/history discovery; both transports delegate to this one core reader, never transport-owned SQL or a second store. Strict `NavigationRequest`/`NavigationResponse` reuse common ErrorResponse and P01 budgets, not the frozen fourteen-operation Request/RunRequest unions. `testing_query_runs` takes `Navigation_queryRuns` and returns `RunPageResult`; `testing_query_observations` takes `Navigation_queryObservations` and returns `ObservationPageResult`. Both require `read`; annotations are readOnly=true, destructive=false, idempotent=true, openWorld=false. Exact IDs/library authority and common decoded-value validation apply before protected reads. Schema roots `/definitions/NavigationRequest`, `/definitions/NavigationResponse`, `/definitions/ErrorResponse`; selector-closure content pin `cc290bdcca6278f423c91f7c079ad387e18dabef21b513d7066f983039f37606`.

`queryRuns` pins retained publication/run-head metadata; complete `(run_id)` ordering includes current-at-that-publication selection/checkpoint/terminal-summary refs, even finalized runs, without unrelated body loads. Empty filters include every retained run; IDs/states use exact filter values. `queryObservations` binds one run and an immutable checkpoint/summary prefix when `prefix_ref` is supplied; null pins current-at-first-page as-of publication/count/prefix digest. Enumerate original append ordinals ascending, with exact observation refs/case refs/attempt/key/outcome metadata. Never infer a new observation or omit an unexecuted canonical observation because of its outcome. Missing executions remain summary gaps, not invented observations.

Use P02 retained publication/observation_links and P03 sealed/as-of prefixes. Cursors bind operation/library/publication/filter/limit/last ID or ordinal and prefix ref/count/digest; checksum is not authority. Later writes disclose drift but do not invalidate an available frozen read. Page limit 1–50, explicit UI default25, serialized whole response ≤24KiB, byte-shortened pages retain continuation and at least one complete item when nonterminal. No GET/read materialization, DDL, repair, migration, recovery or unrelated body loading. Missing/corrupt derived navigation fails explicitly and requests authorized `repairIndex`; never hides runs/results. The new combined workspace build's existing initialize/definition/run write primitives maintain these derived metadata rows; authorized repair rebuilds them from retained refs without changing canonical bytes or the frozen fourteen DTOs. P06 owns this additive application reader/projection integration; it is not native execution or a second journal.

## Settings operation registry

NEW shared application `executeSettings(access,request)` owns per-explicit-library/local-operator preferences, not browser storage or global settings. `testing_get_settings` / `SettingsGetRequest` → `SettingsReadResult` requires read (readOnly=true/destructive=false); `testing_update_settings` / `SettingsUpdateRequest` → `SettingsWriteReceipt` requires read+settings (readOnly=false/destructive=false). Both idempotent=true/openWorld=false; success envelope SettingsResponse, failures exact ErrorResponse. Roots SettingsRequest/SettingsResponse/ErrorResponse use the P01 closure algorithm; pin `01aab545fa683c48abe4e8faa3761864d1ff7725d8751bc0024e9deb197aae41`. These two capabilities are a separate group, not members of frozen CoreRequest14.

Only page_size1..50 (effective absent-row25) and report_title nullable ShortText (absent-row null) are editable. Get returns revision0/default values for an absent row WITHOUT creating/migrating/writing; canonical identity/readiness/version are read-only displays. Store a versioned settings row and identified operation receipt atomically in the SAME owned library DB under cooperative writer safety. Update checks expected settings revision and canonical request digest/ID, increments only settings revision, and preserves prior valid values on invalid/conflict/failure. It never changes case inventory/run/navigation publications, root/grant/command/renderer/retention settings or another operator/library. Exact replay checks receipt before current revision CAS. Get's optional inspect identity returns the original settings receipt/effect after a lost reply before any new intent; unknown effects are not failed-save fiction. No localStorage/ambient project/auto-default persistence. Missing table/layout is an explicit upgrade/repair prerequisite, never GET DDL.

These checks are proposed, NOT run during drafting. Implement Linux/Windows/macOS and stable desktop Chrome/Edge/Firefox/Safari (Safari where applicable on macOS); development verification is Linux + real Google Chrome only. Other supported environments remain unverified, not passed or extra native completion gates.
