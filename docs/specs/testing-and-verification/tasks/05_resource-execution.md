# P05 — Live resource coordination and temporary batch execution

Status: **Technically agreed; implementation and native qualification not performed or authorized.** Packet `P05`, proposal `testing-workspace-05-resources-v2`. Exact managed binding is below. No measured capacity, process-safety pass or execution authority is claimed.

## Role in the two skills

Both `manual-testing` and `regression-testing` need to perform test actions, wait for observable results and retain evidence. This packet supplies their internal script executor. It runs for the duration of a test batch, not as another skill or a permanently running scheduler. The model does not need a separate turn for each routine action or wait.

The executor checks available resources, respects necessary preparation/order constraints, runs independent checks in parallel only when safe, and collects every result. For example, preparing test data may need to finish before a check that uses it. That prerequisite is not a new product feature or service. P04 connects execution to native workflow preparation/assessment; the shared case application records the facts, and Allure renders the resulting report.

### Selected live coordination algorithm

Use [Node 22.20 `node:sqlite`](https://raw.githubusercontent.com/nodejs/node/v22.20.0/doc/api/sqlite.md) on the accepted Node >=22.20.0 baseline: synchronous `DatabaseSync`, rollback journal, `synchronous=FULL`, proposed **100 ms busy timeout**, bounded supervisor retry within the prepared deadline. [BEGIN IMMEDIATE](https://www.sqlite.org/lang_transaction.html) serializes admission; no handwritten multi-file lock protocol or unmeasured durability/performance claim.

Fix one LOCAL area per actual OS account, never per project, caller path or environment override. Let `H = os.userInfo().homedir`, provided by the OS rather than `$HOME` ([Node 22.20](https://nodejs.org/download/release/v22.20.0/docs/api/os.html#osuserinfooptions)). Linux: `H/.local/state/engineer-agent-workflows/coordination`; macOS: `H/Library/Application Support/engineer-agent-workflows/coordination`; Windows: `SHGetKnownFolderPath(FOLDERID_LocalAppData)/EngineerAgentWorkflows/coordination`, resolved for the effective token, not `%LOCALAPPDATA%` ([Microsoft folder contract](https://learn.microsoft.com/en-us/windows/win32/shell/knownfolderid)). No project, XDG/HOME override, Case UI setting or caller flag can select another allowance. Isolated tests inject an owned platform context, never real account state.

The area contains one `authority.json` marker and `coordination.sqlite3`; marker format/realm UUID, effective UID/SID, physical-host identity and database identity must match the committed SQLite realm row. Node filesystem checks reject links/unsafe ownership; new POSIX directories/files use 0700/0600, while the Windows helper verifies token ownership and a protected private DACL. Do not repair existing permissions silently. Refuse network filesystems ([SQLite warning](https://www.sqlite.org/lockingv3.html#how_to_corrupt)). All cooperating roots/projects/renderers share this authority; aliases or another SSH account on the same host must map to the same physical accounting domain/common qualified controller, else allocation blocks rather than gets another RAM budget.

**MANUAL GATE:** explicit operator bootstrap may initialize only a new, exclusively created owned private area. Exclusive marker creation and the committed SQLite identity precede completed initialization; interruption, known missing/corrupt marker/database or mismatch requires recovery/BLOCKED, not fresh namespace, age reset or automatic replacement. Alternate location/realm or migration needs explicit maintenance after verified live-owner quiescence, preserving the canonical marker as the sole authority anchor. Missing privilege is a fail-closed prerequisite, not unsupported-platform policy. No actual initialization or global mutation is authorized here.

The live owner retains a random operation token, native root/session/job context, supervisor PID plus start/boot epoch, attempt, actual process/provider handles and claim/sample epochs. Keep private host/process details out of durable reports. Saved `OwnedHandle`/`Reservation`, PID, heartbeat or TTL alone grants no authority.

Deduplicate resource/physical-host keys. In a short `BEGIN IMMEDIATE`, read all cooperating claims/reservations, obtain or revalidate bounded fresh samples, evaluate every local enforcement domain, and commit the candidate's ENTIRE claim/reservation set or roll back. Recheck freshness before dispatch. Never hold this transaction across execution, remote calls, native waits, chat turns or canonical-data writes. A committed claim survives connection closure as a record, not permission to adopt its resources.

Remote/shared resources require an existing common qualified claim/observe/drain/release controller. Acquire handles in stable order, launch only after all are held/revalidated; failure releases known partial acquisitions, unknown release blocks. **No distributed SQLite atomicity** is promised. Shared accounts need one authority across hosts. Missing coordination permits bounded serial work only when serialization removes contention and all other conditions hold; otherwise block. No controller installation.

Release only this owner's claims after terminal child/stand drain. Owner loss leaves uncertain claims blocked until exact native/process/stand reconciliation establishes safe release through authorized recovery. PID disappearance/age/lease expiry does not prove descendants or non-idempotent effects ended. Corrupt coordination state fails closed; never delete its database/journal or steal claims to continue. Live execution reservations and short canonical-data locks remain distinct.

### Scheduling and memory accounting

Use a stable topological ready queue: cycles, missing/out-of-subset prerequisites and failed setup block affected descendants, not independent safe components. Never silently extend a subset. Every frozen active case/variant, including draft/stale/non-ready cases, remains terminally observed or explicitly blocked; pressure cannot shrink coverage.

Stand placement fixes product/build/configuration, OS/runtime/tools, readiness/reset, data/account isolation, ownership and physical/container/process domains. Alias URLs/containers do not add memory; separate machines do not isolate shared data. Reuse healthy stands. Extra start/reset/stop needs declared operations, per-run authority and admitted demand. Unknown isolation serializes only when sufficient; one worker is not a cross-run lock.

For every execution/browser and managed-stand enforcement domain:

```text
fresh available bytes >= headroom
  + remaining growth of admitted allocations
  + conservative additional peak of candidate
```

Remaining growth is positive declared-peak minus fresh attributable usage ALREADY reflected in available memory, plus committed reservations not reflected in that sample. Reconcile epochs under admission; ambiguous attribution blocks further managed allocation. Do not subtract reflected usage twice, omit in-flight reservations or double-count reused browser/stand aliases. Satisfy nested limits separately. Include supervisor/browser/driver/children; use compatible measured peaks or labeled conservative estimates. Unknown demand/capacity blocks even concurrency one. CPU/process/disk/request budgets, tools, isolation and readiness also apply. CPU count/swap/soft reservations/heap limits are not RAM containment. Unmanaged external targets retain authorized load budgets and honest unavailable remote guarantees.

### Platform providers, finite defaults and lifecycle

Observation adapters, not measured evidence: Linux `/proc/meminfo` available bytes plus resolved cgroup mount/membership/ancestor `memory.max/current` ([kernel](https://docs.kernel.org/admin-guide/cgroup-v2.html#memory)); Windows PowerShell `Get-CimInstance Win32_OperatingSystem` physical free/total ([contract](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-operatingsystem)), with helper-owned process identity; macOS [Node `os.freemem/totalmem`](https://raw.githubusercontent.com/nodejs/node/v22.20.0/doc/api/os.md#osfreemem) is conservative host-only capacity, not container/reclaim guarantees. Required unknown limits/attribution/ownership blocks admission, not installation or Linux fallback.

Retain actual handles: Linux/macOS owned groups; Windows a packaged Node-launched PowerShell/.NET P/Invoke helper solely owns a private non-inherited [Job Object](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects). Use `CreateJobObject`, `SetInformationJobObject(JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE)`, `CreateProcessW(CREATE_SUSPENDED)`, `AssignProcessToJobObject`; resume ONLY after assignment. Failure terminates the suspended owned process; no breakaway or `taskkill`/PID fallback. IPC carries commands/facts; EOF closes the job handle, helper death closes kernel handles. Authorized `TerminateJobObject` plus `QueryInformationJobObject` establishes drain, not cancellation alone. This selects implementation, not existing code/native proof or installation. Missing helper/nested-job privilege is an authorization/qualification MANUAL GATE, not unsupported Windows or an extra Windows-native gate this cycle. Other hard limits require availability/authority.

Proposed, NOT measured defaults: **1 s** sampling plus every admission; **5 s** maximum metric age including clock/source uncertainty; headroom **max(1 GiB, 20% effective capacity)**; **30 s** condition/action deadline; **600 s** batch deadline, configurable to a justified finite value; **5 s** graceful stop/**10 s** total escalation/drain; ceilings **one stand/two workers**, subject to stricter safety/caller/project/native limits. Never lower reserve merely to run. Longer atomic work needs prepared bounds and qualified P04 waiting, not changed expectations.

Pressure, stale telemetry, exceeded limits or stand loss stops admissions immediately. Checkpoint results; release idle owned resources/reduce concurrency safely; threatened running work gets bounded graceful stop and authorized owned escalation/drain. Preserve distinct driver syntax/locator/runtime error, missing output, product assertion, timeout/cancellation, infrastructure OOM and unknown cleanup. Repair gets a new attempt only after P04's all-job barrier and side-effect reconciliation. Cleanup/persistence/driver uncertainty means incomplete; never touch unrelated work. Sampling, condition timers, contention and settlement run in the supervisor, not model turns.

### Verification boundary
