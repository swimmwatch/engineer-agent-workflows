## Adapter authority contract

**NEW common transport boundary, also a P07 source.** Explicit operator startup uses `testing-workspace mcp --library-grant-file <absolute-file>` or `testing-workspace serve --library-grant-file <absolute-file>`. These are ordinary future application entrypoints, NOT collection installers, skill invocation, auto-started daemons or MCP registration. Each reads one operator-owned local JSON `OperatorConfiguration` (≤256 KiB, strict P01 decoded-value rules), with ≤32 exact `(LibrarySelector, root, permissions)` grants. No default current project/root and no environment/global-client mutation. Empty grants allow only minimal runtime information. Unknown options/config fields fail startup, never fall back to permissive access.

Read configuration through a bounded regular owned file; reject links/aliases and insecure permissions (private operator access via POSIX permissions or Windows ACL equivalent; unsupported verification fails closed). Require absolute owned local roots; verify containment, canonical path identity, no escaping symlink/junction/reparse/DB aliases and stored project/library IDs under P02. Deny duplicate/conflicting grants, same physical root under different identities and unsafe case/normalization aliases. An absent library is permitted only by an explicit `initialize` grant plus P02's clean-area rules; merely reading configuration never initializes it. Paths stay private in memory, not public operation DTOs/errors/logs. This is not a sandbox against a malicious process already holding the same OS privileges.

Startup configuration establishes maximum authority, not arbitrary browser access. Per request build binding `trustedPrincipalContext` from this process's verified immutable grants and its authenticated transport session: exact project/library IDs, resolved verified directory identity, granted permission subset and process/session instance. The common application receives it separately from `Operation_*` as `executeOperation(access, request)` and compares selector/record/ref membership BEFORE protected reads/effects. `access` also carries request-local cancellation/deadline information, not caller JSON or stored permission. A stdio process may use its operator-configured grant directly; the browser additionally needs P07's explicitly approved library-scoped session. Both adapters reuse this same authority resolution/core enforcement, never independent interpretations.

Permissions: `read` for open/query/get/inspect/openRun/getRunRecord; `definitions` for commit; `runs` for begin/append/checkpoint/finalize; `initialize` for absent-library creation; `recovery` for repair/recovery, with recovery additionally requiring its original operation permission; `reports` for owned report metadata/generation/recovery/cancellation/access, never SUT execution; ReportService also requires `read` for its frozen inputs. A grant for one library never authorizes another, and source references, cursor/base64 context, process-readable paths or guessed UUIDs are NOT grants. Browser APIs cannot read/change the grant file, browse filesystem roots, broaden permissions or silently retarget a pending request. `settings` is a DISTINCT write grant for library preferences, also requiring read; it cannot change authority. Changes require explicit operator restart, invalidating only this instance's sessions/grants; persisted cases/runs/receipts survive.

**Exact schema binding.** [Schema family](docs/specs/testing-and-verification/contracts/schemas/data.schema.json), Draft 7, `$id=urn:engineer-agent-workflows:testing-workspace:v1`; use P01's selector-closure algorithm. Core → domain/store dependency remains inward; no store/domain SDK import or native SUT orchestration. Private module/helper names are flexible; these responsibilities and public logical names are binding.

Appending independent report sections after the terminator cannot alter this selection; selected rule/schema changes require reconciliation.

Core schema roots/pins remain the shared authority contract. New common `executeNavigation(access,request)` owns metadata-first retained-publication/prefix enumeration, cursor/error/budget parity, derived metadata integration into existing future write/repair primitives and zero read writes. Input/output roots `/definitions/NavigationRequest`, `/definitions/NavigationResponse`, `/definitions/ErrorResponse`, P01 closure pin `cc290bdcca6278f423c91f7c079ad387e18dabef21b513d7066f983039f37606`. This additive shared application reader lives inward of both adapters, not in SQL-owning transports. Missing derived navigation requires explicit authorized repairIndex. Independent P08 report section/tools/DTOs are excluded from this source set; no fake capability, UI launch or installer.

**Settings application unit.** Shared `executeSettings(access,request)` and its separate MCP group implement only page_size/report_title, revision0 no-write defaults and atomic settings row/identified receipt/CAS in the owned library DB. Reuse cooperative writer guards but never change Case inventory/run/navigation revisions or Core14 envelopes. Read+settings write grant is distinct; optional read inspection resolves a lost update reply before a new intent. Missing table is an explicit prerequisite, not read-time DDL. SettingsRequest/SettingsResponse/ErrorResponse exact closure pin `01aab545fa683c48abe4e8faa3761864d1ff7725d8751bc0024e9deb197aae41`.

**Lifecycle/errors.** Per contract: raw stdio frame 2 MiB, decoded canonical request 1 MiB, response 24 KiB and duplicated MCP result 64 KiB; common depth/count/schema constraints; four admitted operations, no hidden queue; 15-second cooperative core deadline, 1-second SQLite lock wait, no false hard-interrupt claim. Validate successful output before projection, preserve committed/uncertain effects on serialization/disconnect. Domain failures are exact ErrorResponse + `isError=true`; malformed protocol/unknown tools use bounded SDK errors. Cancellation/disconnect does not kill jobs or imply rollback; inspect original ID/digest before exact replay/recovery. Read-only operations never repair/create. EOF/close releases only owned transport/core handles and leaves other MCP/HTTP processes and host work alone.

**Alternatives/recommendation.** Recommend the existing low-level SDK factory plus generated common JSON Schemas: it preserves bounded core errors and exact shared DTOs with no schema duplication. The SDK's high-level server with manually authored Zod objects would be convenient for small independent tools but duplicates this canonical family and risks coercion/error drift; a high-level wrapper generated from the same selectors could be equivalent, but supplies no demonstrated simplification here. A mandatory daemon/proxy is already excluded by the shared agreed architecture, not offered as an unselected second solution. No new HTTP/framework dependency is needed for stdio.

**Verification boundary.** After agreement, later packet details must map RED/GREEN/PROVE to exact discovery/schema/annotation identity, all operation/result pairs, invalid/foreign/CAS/lost-reply parity, cancellation/bounds/read-only access and owned EOF/close. SDK client tests are future checks, not executed now. Implement all three runtime OSes; UI/browser support remains all four desktop families including Safari on macOS. Required development execution stays Linux + real Google Chrome ONLY; no extra all-platform native gate or fabricated native pass. Normal application startup/configuration/recovery needs durable developer documentation in the parent's later documentation packet.
