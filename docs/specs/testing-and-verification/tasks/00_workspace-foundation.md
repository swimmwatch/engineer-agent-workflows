**Binding significant units.** Create only the new package's production/build/test area, `packages/testing-workspace`, and the root dependency lock update needed for its workspace dependencies; do not modify existing workflow business modules or generated skills. Bind the package name, executable and dependency/runtime baseline from the shared source. Use a normal npm workspace manifest with `bin` → `dist/main.js`, a TypeScript build, strict NodeNext/ES2023 compilation and isolated Node tests discovered by the existing [root runner](scripts/run-tests.mjs#L152-L205). Keep package scripts usable through the existing [workspace build/lint convention](package.json#L11-L28); do not add a lifecycle installer, global registration or a second server framework. Build/test infrastructure and manifests are real outputs, not empty files passing presence checks.

- `src/main.ts` is the binding process/argument ownership point. With no arguments or exactly `--help`, print bounded usage to stdout and exit zero without starting MCP or opening a project. Exactly `--version` prints the package name and installed package version to stdout and exits zero. Exactly `mcp` starts the SDK endpoint. Reject unknown commands/options and extra arguments with a fixed bounded usage diagnostic on stderr, empty stdout and exit code 2; do not echo an untrusted argument or private path. Do not advertise `serve`, UI, case/run tools or report generation as available. No startup command downloads, installs, migrates, reads a project library or changes client/global configuration.
- `src/server.ts` is the binding SDK server-factory ownership point, exporting `createServer`. It creates a fresh SDK `Server` with this package's own name/version and tools capability, never the engineering-workflow server identity. Provide a small code-injected registration seam for later packet-owned tools; P00's main supplies no registrations. An optional registration callback is invoked once per server, not loaded from project data/configuration or a dynamic plugin system. `createServer(registerTools?)` is an illustrative signature; callback/type/helper spelling remains flexible. Empty production registration must yield `tools/list` with an empty tools array. Use the SDK's actual initialize/initialized negotiation and transport, not a handwritten protocol emulator, synthetic fixture response or application-success stub. An unknown tool/method must follow protocol failure behavior, never dispatch to a pretend Case/Run/Renderer implementation.
- The manifest, `tsconfig.json` and build wiring own reproducible source→dist compilation and package entry resolution. Reuse the current repository's [SDK dependency versions](packages/engineer-agent-workflow-mcp/package.json#L24-L41) and [compiler configuration pattern](packages/engineer-agent-workflow-mcp/tsconfig.json#L2-L17), not imports from that package's business code. `test/` owns focused CLI, factory and real child-process stdio checks. Individual test filenames and private helpers are illustrative, not additional public interfaces. Do not add domain/store/HTTP/renderer scaffolding or unused Ajv initialization merely to pre-create later architecture.

**Flow and owned lifecycle.** Argument validation finishes before any transport is created. The `mcp` branch composes its fresh factory with SDK `serveStdio` and `StdioServerTransport`, following the existing [startup and close pattern](packages/engineer-agent-workflow-mcp/src/main.ts#L1-L19). The client completes standard initialization, sends `notifications/initialized`, and obtains the truthful empty tool list. During MCP mode stdout contains protocol messages only, without banners, help text or logs. Normal startup/requests are quiet on stderr; transport/startup/close failures use bounded fixed diagnostics without stack traces, source bodies or private absolute paths, and an unsuccessful owned close is not reported as success. EOF, SIGINT and SIGTERM close only this process's owned transport/server handles. Make close idempotent for competing shutdown notifications; do not kill another process, acquire project authority or touch native test jobs. Help/version branches never own a server.

**Rationale and verification boundary.** This is the smallest coherent first deliverable for the mandatory separate runtime.
