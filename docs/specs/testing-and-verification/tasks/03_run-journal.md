## Technical proposal

**Ownership/API.** Extend NEW `packages/testing-workspace` core using P01 invariants/P02 atomic CAS/publication/receipts, never another journal/skill copy. Binding operation/result pairs: `beginRun → WriteReceipt`, `openRun → RunHeadResult`, `appendObservations → WriteReceipt`, `checkpointRun → WriteReceipt`, `finalizeRun → WriteReceipt`, `getRunRecord → PortionResult`; exact P01 `Operation_*` inputs, separate trusted authority. No domain/store dependency on transports/native execution. Private names flexible.

**Freeze once.** `beginRun` validates the complete retained inventory/ref set, not a count/first page, and expected current publication before saving immutable `RunSelection`, revision 1. Full mode requires empty explicit case/suite selectors and includes ALL active cases and active suite expansion: unsuited, manual, unautomated, draft and stale included. Retired definitions are explicit exclusions with provenance. Subset requires nonempty explicit selection, is labeled subset, and excludes other/retired definitions explicitly. Retired members cannot disappear silently. Non-ready active cases retain required denominator positions with prerequisite issues; absent tools/oracles/implementation never become hidden exclusions.

Expand flat canonical suites, combine direct and member cases by exact ID/revision, validate targets and unique supplied `(variant,target_id)` rows. For each selected case and row, execution key is SHA-256 of P01 canonical JSON `[case_id,case_revision,environment_key,parameter_key,repetition,target_id]`. Overlap deduplicates exact keys; explicit repetitions remain distinct. Freeze exact inventory/suite/case refs, build/environment/physical-host/authority provenance, variants, prerequisite issues and exclusions. Missing subset dependencies block affected executions, never broaden scope. Reject dangling/contradictory definitions; retained case dependency cycles or combined selected order cycles mark affected prerequisites, not missing coverage. Deterministic topological order uses `(case_id,variant tuple,target_id)` for ties, retaining cyclic rows as blocked in that order. This is a data ordering description, NOT a scheduler/admission mechanism. Validate execution/byte limits before save. Later definitions/results cannot rewrite selection; disclose frozen-versus-current inventory drift. An available historical snapshot remains readable but does not authorize stale begin-run CAS.

**Append facts, not successful stories.** Begin establishes run revision 1. Every append/checkpoint/finalization publication increments run revision once; expected run revision serializes writers independently of definition revisions. Persist immutable observations with unique IDs and unique `(run_id,execution_key,attempt)`, attempt 1–32, monotonically increasing per execution; different content at the same attempt conflicts. Match project/library, case ref and execution key to frozen selection. Preserve every attempt, script/infrastructure error and earlier product violation; do not rewrite expectations or retire a failing case. Appending observations must not invalidate P02 case pagination. Request replay returns its original receipt without another append; changed same-ID content conflicts before effects.

Exactly six outcomes: PASS = observed expected applicable behavior; FAIL = confirmed observed product violation, independent of root-cause confidence; BLOCKED = missing prerequisite/authority/capability; NOT_RUN = not executed; INCONCLUSIVE = insufficient/ambiguous evidence; NOT_APPLICABLE = genuinely outside applicability with cited justification, never missing implementation/tools. PASS/FAIL require a ready frozen case, actual observation, method/evidence and coherent class (`none`/`product`). Non-ready selections cannot receive product PASS/FAIL. Driver/infrastructure failures remain explicitly classified BLOCKED/INCONCLUSIVE/NOT_RUN as appropriate, not product passes/failures. Runtime validates identity/consistency, not independent truth of caller claims. All required no-observation executions remain explicit NOT_RUN gaps in derived summary, not fabricated journal observations.

**Checkpoint and inspection.** `openRun` returns exact selection/checkpoint/summary refs, run revision, observation count, stored execution phase and report delivery separately from canonical verdict/persistence. These are saved facts, never a live poll. `getRunRecord` uses P02 exact ref/publication/prefix-bound portions; later appends cannot substitute bytes or stale available continuations. Checkpoint input contains only caller facts. Store fills identity, selection ref and exact immutable observation-prefix count/digest; compute digest of canonical ordered observation refs by append ordinal. Prefix links are retained atomically, so every referenced observation can be enumerated without embedding 100,000 refs in each checkpoint. Stable checkpoint ID, revisions 1 then +1; distinct from run-head revision.

Retain phase, plan/dependencies, OwnedHandle/Reservation facts, outputs, completion/cleanup/persistence and resume requirements. `execution_facts` records native host/owner/session/job IDs, operation/stage/batch/attempt epoch, driver digest, launch_intent/started/terminal/unknown, cleanup and metric provenance. `external_stage_artifacts` binds artifact/source digest and bounded page refs/cursors; validate unique in-range pages, complete-page count and selection-bound execution keys. Facts NEVER grant live ownership. Resume owner rechecks actual jobs/target/permission/capacity; no duplicate live/non-idempotent work. Waiting is not cancellation. No provisioning, job control, product fixes or packet advance.

**Canonical verdict.** Finalize requires checkpoint prefix equal to current append prefix and complete accounting. For each frozen execution, any confirmed product FAIL in ANY attempt wins, including intermittent FAIL followed by PASS; otherwise choose greatest explicit attempt. Missing keys count NOT_RUN. Counts sum to frozen denominator; justified NOT_APPLICABLE stays visible. Derive exactly FAILED if any applicable product FAIL; else INCOMPLETE for any required BLOCKED/NOT_RUN/INCONCLUSIVE/missing key, unresolved required driver error, uncollected/nonterminal job, missing output, failed/unknown required definition/run/report persistence or cleanup, or no applicable executed checks; otherwise PASSED for frozen stated scope ONLY. Optional gaps remain limitations. An all-excluded/empty run cannot pass; successful save/API/renderer exit is not test success. `not_required` facts need cited applicable-scope justification.

Phase, verdict, run/definition/report persistence and `report_delivery=pending|generating|ready|failed|unavailable` differ. Preserve product FAILED plus delivery gaps; unmet required delivery otherwise prevents PASSED. Summary cites exact facts/prefix, not later live state. Save summary/receipt atomically; only COMMIT acknowledges save, unknown means inspect. Finalization seals observations/checkpoints. Later `finalizeRun` may append a NEW immutable summary revision using same ID, exact `expected_summary_ref`, current run revision and refreshed completion facts over SEALED prefix; first finalization requires null expected summary ref. Thus delivery recovery does not rerun tests/rewrite old reports. Retests need new run ID/`prior_run_id`; preserve earlier failures and separate failed definition maintenance.

**Future qualification.** Fresh-process isolated reads check refs/prefix/counts, complete full inventory, exclusions/dedup, stale CAS, wrong refs/attempts, FAIL→PASS, driver/missing-output/job/save gaps and delivery reconciliation. Verify unchanged definition bytes, complete pagination during appends and zero job execution from record access. P02 owns crash mechanisms; schema fixtures prove neither durability nor real execution. 1000 cases/100 suites is input only. Development evidence: Linux + real Google Chrome; others supported/unverified, no extra native gate. Detailed RED/GREEN/PROVE maps/checklists follow agreement outside this section.
