## Source-audit follow-up

The authorized follow-up removes repeated work inside an audit without setting
a fixed wall-time deadline. Reuse exact immutable bytes, parsed YAML/JSON and
Markdown, full generations, reconstructed review inputs and verified predecessor
audits only inside that audit. Metadata-only generation inspection must never
satisfy a full generation audit. Keep parser contracts distinct and include
store, object identity, digest and validation strength in the relevant keys.

Use one fully validated lineage traversal for ready PRD and Technical Design.
Roadmap authoring consumes the document loader's validated snapshot instead of
loading the same candidate, registry and draft Markdown a second time. Preserve
membership, direct-edit, lineage, source, schema and integrity checks.
Read independent generation sources in groups of at most four. Preserve source
ordering and finish all reads in the current group before surfacing an error;
parallel I/O must not omit any source validation or carry reuse across phases.

Mutation entry and immutable writes invalidate preflight reuse. Each under-lock
source check starts a fresh audit; mutable candidates, reviews, head and bindings
retain their existing checkpoints. Memoized history must preserve cycle and depth
checks, and mutable predecessor bytes must still be checked on each access.
Public MCP requests, responses and persisted formats remain compatible.

Acceptance requires discriminating RED/GREEN checks for audit reuse and fresh
transaction verification, inherited-history and source-corruption regressions,
and three representative native plus three stdio measurements before and after.
Report retirement, review, correction, activation and replay separately, including
physical reads, parsed inputs, audit reuse, source bytes and protocol delivery.
Confirm a measured reduction rather than claiming the previous 120.7-second
scenario is an acceptable deletion latency. Model time remains outside these
synthetic server measurements.

## Followup correction diagnostics

For an otherwise mappable correction with incomplete `fixes[].changed_refs` or
finding-linked prose keys, retain `PREREQUISITE_REQUIRED` and return bounded,
deduplicated diagnostics identifying exact missing references/item keys and the
`complete_correction_mapping` next action. Include retained retired-task
provenance and dependency participants carried by changed semantic blocks.
Report truncation explicitly; omit source text and machine paths. The caller can
complete the mapping and retry followup without starting a full review.

Preserve full-review requirements for unmappable changes, the consistency-finding
requirement for prose, source/history checks, fresh judgments and read receipts.
Do not write review state for a rejected mapping or change request schemas,
stored formats or recovery authority. Verify the diagnostic and corrected retry
through public MCP, bounded large-reference errors and unchanged integrity gates.
