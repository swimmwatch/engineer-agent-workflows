# Packet b1-02: summarize with shared validation

## Technical proposal

Binding proposal `b1-summary-v1`, packet `b1-02`, requirements B1-002 through B1-005 and B1-001 compatibility. Include the exact `Shared technical contract` section of `docs/specs/b1/tasks/plan.md` as a binding source. Depend on completed b1-01 and consume its `parseRecords(text)` unchanged. Add proposed pure export `summarizeRecords(records)` in `records.mjs`, accepting only fully validated records, returning `{count: number, total: bigint}` with per-call state and no input mutation. Accumulate `BigInt(record.amount)` starting from `0n`; never sum in Number or convert the aggregate to Number. Extend CLI dispatch to read/decode/validate via the same path as validate, then summarize. Format a fixed JSON object using the decimal `total.toString()` as an unquoted integer token and count as an integer, with one complete stdout write after success. Do not pass a BigInt directly to JSON.stringify. This owns exact serialization rather than changing JSON globally. Count and total are zero for no records. Minor formatter helper names remain flexible. Tests use the existing subprocess helper and exact raw stdout tokens for large totals, retaining validate/help/error checks. BigInt provides exact built-in arithmetic; manual decimal-string addition would also work but adds carry logic and tests without a benefit for this dependency-free Node fixture.
