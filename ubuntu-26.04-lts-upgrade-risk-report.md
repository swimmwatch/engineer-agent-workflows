# Отчёт о рисках обновления Ubuntu 24.04 LTS → 26.04 LTS

> Локальный предмиграционный аудит ноутбука Acer Predator PHN16-73
> (`home-laptop`) от 2026-07-26. Никакие пакеты, репозитории, службы,
> настройки или данные во время проверки не изменялись.
>
> Документ содержит сведения о конкретном компьютере и установленных
> программах. Не добавлять в Git и не публиковать без предварительного
> просмотра.

Связанные локальные документы:

- [полный диагностический отчёт](./laptop-diagnostic-report.md);
- [реестр выявленных проблем](./laptop-diagnostic-problems.md).

> **Актуализация 2026-07-27:** повторная read-only загрузка подтвердила
> NVIDIA 595.84 без Xid/API mismatch/display timeout и сохранение нужной
> X11-раскладки после reboot. BIOS уже обновлён до V1.26. При этом UCSI/ACPI
> warnings сохранились, в старте появилось 16 `NvKmsKapiMemory`, а Discord
> Snap снова создаёт активный AppArmor/audit-поток. Для Docker, dpkg backup,
> AmneziaVPN, Outline и Happ теперь `NeedDaemonReload=no`. Эти улучшения не
> меняют общий NO-GO: официальный переход всё ещё закрыт, backup/SMART и
> целевой GNOME 50 Wayland-тест не выполнены.

## Короткий ответ

**Сейчас обновляться не следует.**

Ubuntu 26.04 LTS уже выпущена, но штатный переход для пользователей Ubuntu
24.04 LTS ещё не открыт. Официальный `meta-release-lts` показывает для
26.04 `Supported: 0`. Актуальный график Canonical назначает выпуск
Ubuntu 26.04.1 на **27 августа 2026 года**. До переключения на `Supported: 1`
не использовать `do-release-upgrade --devel-release`, `-d` и не заменять
`noble` на `resolute` вручную.

Даже после открытия обновления этот ноутбук нельзя считать готовым без
подготовки. Главные стоп-факторы и риски:

1. Ubuntu Desktop 26.04 использует GNOME только на Wayland, а текущая
   исправленная конфигурация мониторов специально зависит от X11.
2. Проверенной резервной копии нет.
3. Остаётся неподтверждённо исправленной проблема USB-C/DisplayPort.
4. Старый monitor-autostart использует `xrandr`, Mutter layout mode `3` и
   X11-координаты; на Wayland его запуск небезопасен.
5. Есть 10 работающих Docker-контейнеров и 43 Docker volume общим размером
   около 23,25 GB.
6. Пять Pipx-окружений привязаны к системному Python 3.12, тогда как в
   Ubuntu 26.04 системный Python — 3.14.
7. Release upgrader, как правило, отключает сторонние APT-источники; на этом
   ноутбуке таких активных источников 12, и каждый придётся проверять отдельно.

### Вердикт

| Сценарий | Оценка |
| --- | --- |
| Форсировать обновление сегодня | **НЕ ГОТОВО, высокий риск** |
| Обновиться сразу после появления 26.04.1 без подготовки | **НЕ РЕКОМЕНДУЕТСЯ** |
| Обновиться после выполнения всех условий GO из раздела 14 | **Допустимо, средний риск** |
| Остаться на 24.04 LTS | **Безопасный вариант; стандартная поддержка продолжается до мая 2029 года** |

Утверждать, что «всё точно будет хорошо», нельзя. Наиболее вероятный успешный
результат после правильной подготовки — рабочая система, но с повторной
настройкой мониторов, пересозданием Pipx-окружений и повторным включением
совместимых сторонних репозиториев.

## 1. Официальное состояние обновления

### Какая версия является последней LTS

- Текущая система: Ubuntu 24.04.4 LTS `noble`.
- Последняя выпущенная LTS: Ubuntu 26.04 LTS `Resolute Raccoon`.
- Ubuntu 26.04 выпущена 23 апреля 2026 года.
- Стандартная поддержка Ubuntu 26.04 продолжается до мая 2031 года.
- Стандартная поддержка Ubuntu 24.04 продолжается до мая 2029 года.

Штатный прямой путь существует: **24.04 LTS → 26.04 LTS**. Промежуточные
24.10/25.04/25.10 для LTS-перехода не нужны.

### Почему обновление пока не предлагается

На момент аудита официальный файл
`https://changelogs.ubuntu.com/meta-release-lts` содержит:

```text
Dist: resolute
Name: Resolute Raccoon
Version: 26.04 LTS
Supported: 0
```

Локальная политика настроена правильно:

```text
/etc/update-manager/release-upgrades
Prompt=lts
```

Пустой локальный файл
`/var/lib/ubuntu-release-upgrader/release-upgrade-available` согласуется с
официальным gate: обычное LTS-обновление ещё не разрешено.

Первоначальное объявление релиза упоминало 4 августа, но более новый
официальный график, обновлённый Canonical, перенёс выпуск 26.04.1 на
**27 августа 2026 года**. Использовать нужно более свежую дату из графика.

### Чего не делать

- Не запускать `sudo do-release-upgrade --devel-release`.
- Не использовать сокращение `-d`.
- Не заменять `noble` на `resolute` вручную в APT-файлах.
- Не подключать чужие скрипты «обновления в один клик».
- Не обновляться по нештатному пути только потому, что ISO 26.04 уже доступен.

Официальная документация предупреждает, что обновление development release
не поддерживается и может сломать систему. В данном случае `Supported: 0`
также означает, что Canonical ещё не открыл массовый LTS-переход.

## 4. Главный риск: X11 меняется на обязательный Wayland

### Что официально меняется

Ubuntu Desktop 26.04 использует GNOME 50. Ubuntu Desktop session теперь
работает только на Wayland, потому что GNOME Shell больше не может работать
как X.org-сессия. X11-приложения продолжают запускаться через XWayland, но
полноценной GNOME X11-сессии больше нет.

Другие рабочие столы, например KDE, Xfce или MATE, всё ещё могут работать
через X11. Однако их установка была бы отдельной миграцией рабочего стола, а
не прозрачным обновлением текущего GNOME.

### Почему это особенно важно на данном ноутбуке

Текущая рабочая схема специально исправлена для GNOME 46 + X11:

- BenQ 4K `DP-1`: 200%, основной;
- AOC Full HD `HDMI-0`: 100%, справа;
- экран ноутбука `eDP-1-1`: выключен;
- X11 framebuffer: `7680×2160`;
- в `monitors.xml` AOC имеет физическую X11-координату `x=3840`;
- пользовательский autostart проверяет схему через `xrandr`;
- тот же скрипт вызывает Mutter D-Bus с `layout-mode=3`.

Файлы:

- `~/.config/monitors.xml`;
- `~/.local/bin/restore-external-monitor-layout`;
- `~/.config/autostart/restore-external-monitor-layout.desktop`;
- `/etc/gdm3/custom.conf`;
- `/etc/modprobe.d/nvidia-graphics-drivers-kms.conf`.

Эта конфигурация **не является переносимой на Wayland**:

- `xrandr` в Wayland видит XWayland, а не реальную конфигурацию Mutter;
- имена выходов могут измениться;
- X11-координата `x=3840` была выбрана из-за специфической проверки
  Mutter 46/X11;
- Wayland использует другую логическую геометрию масштабированных экранов;
- `layout-mode=3` и проверка framebuffer относятся к текущей X11-схеме.

Старый autostart на Wayland может 30 секунд повторять неуспешные попытки,
записать ошибку либо применить неподходящую схему. Переносимость текущего
`monitors.xml` на Wayland не подтверждена: он может сохраниться, потребовать
пересоздания или привести к fallback с включённым экраном ноутбука. В отличие
от этого, несовместимость X11-части autostart подтверждена самим использованием
`xrandr`.

### Что сделать до обновления

Обновляться нельзя, пока не выполнен контролируемый Wayland A/B-тест на
текущей Ubuntu 24.04:

1. Сделать резервные копии четырёх файлов конфигурации мониторов/GDM.
2. Временно отключить monitor-autostart.
3. Временно убрать `WaylandEnable=false`.
4. Первый вход выполнить только на встроенном экране ноутбука.
5. Затем подключать по одному HDMI и USB-C/DP.
6. Настроить BenQ 200%, AOC 100%, встроенный экран off через GNOME Settings.
7. Проверить повторный вход, reboot, hot-plug и suspend/resume.
8. Проверить XWayland-приложения: Chrome, VS Code, JetBrains, Steam, OBS,
   GPT-Voice/OpenWhispr и файловые диалоги.
9. Если тест неудачен, вернуть X11 и остаться на Ubuntu 24.04.

Этот тест потребует изменений и перезапуска сеанса; в рамках данного аудита он
не выполнялся. Успех на GNOME 46 будет только обязательной базовой проверкой,
но не доказательством работы GNOME 50. Перед настоящим обновлением нужен также
целевой тест Ubuntu 26.04 на клоне системы или запасном SSD. Live USB полезен
для грубой проверки портов, но не проверит установленную NVIDIA 595, миграцию
пользовательских настроек и сохранение схемы после обновления.

### Аналогичные открытые сигналы Ubuntu 26.04

В Launchpad есть отдельные открытые отчёты с одним или небольшим числом
пользователей. Они не доказывают, что данный ноутбук обязательно сломается, но
усиливают необходимость теста:

- RTX 5070 + NVIDIA 595-open: потеря физических HDMI/DP-выходов после
  обновления kernel/module;
- Blackwell hybrid laptop + Wayland + 595: краткие GNOME-freeze при
  пробуждении dGPU;
- внешний HDMI перестал работать после обновления до 26.04;
- NVIDIA 595 + Wayland + mixed-refresh/per-monitor scaling: неверные
  XWayland-режимы и лаги X11-приложений.

Часть отчётов относится к более ранним 595.58/595.71, тогда как здесь уже
работает 595.84. Поэтому это сигналы риска, а не подтверждённые блокеры.

## 5. NVIDIA, ядро и загрузка

### Положительные факторы

- Версия 595.84 доступна и в Ubuntu 26.04.
- Текущий kernel module, userspace и NVML согласованы.
- Текущая загрузка не содержит Xid, API mismatch или display-engine timeout.
- Ядро 26.04 и текущее HWE-ядро относятся к Linux 7.0.
- Secure Boot выключен.
- Release notes 26.04 сообщают об исправлении конкретного Wayland-сбоя
  suspend/resume на системах, где NVIDIA является основной GPU, и об улучшении
  плавности GNOME на NVIDIA. Это положительный сигнал, но не подтверждение
  исправления локального mixed-DPI/USB-C сценария.

### Оставшиеся риски

- В загрузке 26 июля были 48 сообщений
  `Failed to get memory pages for NvKmsKapiMemory`; в повторной загрузке
  27 июля — 16, сгруппированных около старта/перестройки дисплеев. После
  09:46:20 новых нет.
- Были шесть UCSI/USB-C-ошибок регистрации cable/partner alt modes. Они могут
  быть связаны с нестабильностью USB-C/DP, но сами по себе не доказывают
  физическое отключение DP Alt Mode.
- Текущий DKMS явно собран только для `7.0.0-28-generic`.
- Для установленного запасного `6.17.0-40-generic` команда `modinfo -k`
  не находит NVIDIA-модуль.
- GRUB скрыт: `GRUB_TIMEOUT_STYLE=hidden`, `GRUB_TIMEOUT=0`.
- Ubuntu 26.04 использует Dracut как новый default initramfs framework, хотя
  `initramfs-tools` остаётся поддерживаемым.

### Требования к recovery path

Перед обновлением:

1. Не удалять текущие рабочие kernel `7.0.0-28` и NVIDIA 595.84.
2. Не соглашаться удалять последнее известное рабочее ядро как obsolete.
3. Подготовить реальный графический fallback: либо установить и проверить
   NVIDIA-модуль для запасного `6.17.0-40-generic`, либо фактически проверить
   загрузку через iGPU/nouveau/текстовую консоль. Сейчас само наличие ядра 6.17
   без NVIDIA-модуля не является полноценным графическим fallback.
4. Сделать GRUB-меню доступным либо заранее проверить клавишу его вызова.
5. Иметь загрузочную флешку Ubuntu.
6. Записать, как попасть в BIOS (`F2`) и boot menu (`F12`, если включено).
7. Проверить, что для нового целевого ядра NVIDIA-модуль действительно
   установлен до первого reboot.
8. После reboot проверить `nvidia-smi`, `dkms status` и журнал до подключения
   обоих внешних мониторов.

## 6. Резервная копия и откат

### Текущее состояние

Déjà Dup установлен и указывает на Google backend, но:

```text
last-backup ''
last-run ''
periodic false
```

Timeshift, Borg и Restic не настроены. Корень — обычный ext4 без LVM/Btrfs
snapshot. Следовательно, быстрого атомарного отката всей системы нет.

### Что обязательно сохранить

В проверенное внешнее или удалённое хранилище:

- весь `$HOME`, включая скрытые конфигурации;
- проекты, незакоммиченные изменения и локальные базы;
- SSH/GPG-ключи и секреты — только в зашифрованной копии;
- `~/.config/systemd/user`;
- `~/.config/monitors.xml`,
  `~/.local/bin/restore-external-monitor-layout`,
  `~/.config/autostart/restore-external-monitor-layout.desktop` и
  `/etc/gdm3/custom.conf`;
- изменённый `/etc/modprobe.d/nvidia-graphics-drivers-kms.conf` с параметрами
  KMS и сохранения видеопамяти;
- список APT-источников и установленных пакетов;
- список Snap и расширений VS Code;
- настройки JetBrains и Toolbox;
- VPN-конфигурации;
- Docker Compose, `.env`, сертификаты и секреты;
- логические дампы PostgreSQL;
- данные MinIO и Weaviate;
- настройки OBS, GPT-Voice и OpenWhispr;
- `/opt/AmneziaVPN`, `~/.config/AmneziaVPN.ORG` и custom unit Amnezia;
- оба Outline AppImage из `~/Desktop/Outline`,
  `/usr/local/sbin/OutlineProxyController`, custom unit и autostart Outline;
- бинарник/пакет Tuna и `~/.config/tuna/tuna.yml`;
- важные Firefox, Thunderbird, Telegram и Steam-данные;
- модели Ollama, если 8,2 GB не хочется скачивать повторно.

При вопросе upgrader о замене NVIDIA/GDM conffile нельзя автоматически
выбирать «оставить» или «заменить»: сначала сохранить обе версии, затем
сравнить параметры с требованиями Ubuntu 26.04 и драйвера 595.84.

Копировать работающий каталог PostgreSQL напрямую нельзя: нужна согласованная
логическая копия или остановленный сервис.

### Проверка копии

Недостаточно увидеть, что backup «завершён». До обновления нужно:

1. Восстановить несколько случайных файлов в отдельный каталог.
2. Проверить открытие восстановленного архива/репозитория.
3. Развернуть или хотя бы прочитать структуру дампа PostgreSQL.
4. Проверить список объектов MinIO.
5. Убедиться, что известны пароли/ключи шифрования резервной копии.

### Важное ограничение

Ubuntu не поддерживает downgrade установленной системы с 26.04 обратно на
24.04. Реальный откат — восстановление полного образа/снимка либо чистая
установка Ubuntu 24.04 с возвратом данных.

## 7. Docker и контейнерные данные

Текущее состояние динамическое, на момент аудита:

- Docker CE `29.6.2`;
- containerd `2.2.6`;
- 10 работающих контейнеров;
- 43 Docker volume;
- все 43 volumes вместе занимают около 23,25 GB; 20 помечены активными;
- Docker оценивает около 17,57 GB volumes как reclaimable, но это не означает,
  что данные безопасно удалять;
- images занимают около 53,61 GB;
- build cache занимает около 88,63 GB;
- live restore выключен;
- контейнеры используют restart policy `always` или `unless-stopped`.

В контейнерах есть PostgreSQL, MinIO, Redis, Weaviate и pgAdmin. Основные
Compose-проекты находятся, в частности, в:

- `~/PycharmProjects/dt/kap-app`;
- `~/PycharmProjects/dt/tma-edtech-app`.

### Риск

Docker установлен из `download.docker.com`, то есть это сторонний репозиторий.
Release upgrader может его отключить. Репозиторий Docker для `resolute` уже
существует, но включать его следует только после завершения OS-upgrade и
проверки официальной инструкции Docker.

Ubuntu 26.04 включает Docker 29 и документирует breaking changes, однако
текущий Docker CE уже версии 29.6.2. Значит, основной риск здесь — не переход
между major-версиями, а отключённый repository, перезапуск daemon и сохранность
данных.

### Что сделать

1. Классифицировать все volumes по Compose-проектам и mounts.
2. Сделать согласованные логические резервные копии PostgreSQL и
   невоспроизводимых данных MinIO/Weaviate; сохранить сертификаты и прикладные
   данные. Для Redis сначала определить, является ли он только кэшем или
   содержит долговечные очереди/состояние.
3. Не копировать без разбора воспроизводимые `node_modules`, cache, venv и
   прочие временные volumes.
4. Сохранить Compose-файлы, `.env`, сертификаты и секреты.
5. Проверить восстановление копий.
6. Запланировать maintenance window.
7. Корректно остановить Compose-проекты перед release upgrade.
8. Не выполнять `docker system prune`.
9. Не удалять «unused» volumes без ручной проверки: там могут быть данные
   остановленных проектов.
10. После обновления включить совместимый Docker repository, выполнить
    `docker compose up -d` для каждого сохранённого проекта, сверить mounts и
    volumes и только затем проверять healthchecks и данные.

Образы и build cache резервировать необязательно: их можно скачать или
пересобрать. Сохранять обязательно не все volumes, а только классифицированные
невоспроизводимые данные. Оценка Docker `reclaimable` сама по себе не является
разрешением на удаление.

## 8. Python, Pipx, Node.js и инструменты разработки

Ubuntu 26.04 меняет системный Python с 3.12 на 3.14.

Пять Pipx-окружений привязаны к `/usr/bin/python3.12`:

- Ansible;
- Ansible Core;
- MarkItDown MCP;
- Poetry;
- uv.

MarkItDown MCP запускается как пользовательская systemd-служба через venv
Pipx и является наиболее вероятным явным отказом после удаления Python 3.12.
Старые venv не следует чинить копированием интерпретатора: их нужно
пересоздать новым Pipx/Python.

Аудит Pipx не охватывает проектные `.venv`: их shebang и symlink тоже могут
указывать на `/usr/bin/python3.12`. Такие окружения не следует переносить в
backup как готовые к запуску. После обновления их нужно пересоздать из
`pyproject.toml`, lock-файлов или requirements и заново прогнать тесты.

Другие компоненты:

- Headroom использует отдельный uv-managed CPython 3.14.3 — риск ниже.
- CloakBrowser закреплён на NVM Node 24.14.0 — системный Python ему не нужен.
- Ollama установлен в домашнем каталоге и зависит главным образом от
  NVIDIA/CUDA.
- JetBrains Toolbox и IDE используют собственные runtime — риск низкий.
- VS Code сохранит настройки, но Microsoft repository может быть временно
  отключён.
- 84 Node.js/Python-проекта имеют `.trackerignore`; после обновления
  LocalSearch нужно проверить повторно.

### План

До обновления сохранить:

- вывод `pipx list`;
- версии Python/Node/uv/Poetry/Ansible;
- пользовательские systemd unit-файлы;
- lock-файлы проектов.

После обновления пересоздать Pipx-окружения на новом `python3`, затем проверить
MarkItDown MCP, Ansible, Poetry и uv.

## 10. VPN, DNS и сеть

Установлены несколько сторонних сетевых стеков:

- daemon AmneziaVPN;
- Outline controller и клиент;
- daemon Happ;
- общий `openvpn.service`.

Работающие daemon не доказывают, что сейчас поднят туннель каждого продукта.
`openvpn.service` имеет состояние `active (exited)` и сам по себе не означает
активный OpenVPN-профиль. При подключении эти продукты могут менять TUN, DNS,
маршруты, iptables/nftables и systemd-resolved. В предыдущих журналах
AmneziaVPN уже регистрировал ошибки DNS, маршрутов и cgroup.

На первичном снимке `docker.service`, `dpkg-db-backup.service` и custom units
AmneziaVPN, Outline и Happ показывали `NeedDaemonReload=yes`. После reboot и
повторной проверки 27 июля все пять показывают `NeedDaemonReload=no`; этот
preflight-пункт сейчас нормализован. Отдельно остаётся warning об executable
permission у unit-файла AmneziaVPN.

Ubuntu 26.04 использует systemd 259 и больше не поддерживает cgroup v1.
Текущая система уже загружена с cgroup v2, поэтому это не прямой блокер.
Однако VPN-сервисы всё равно нужно проверять из-за сетевых и firewall-изменений.

До обновления:

1. Сохранить custom unit-файлы AmneziaVPN, Outline и Happ.
2. Выполнить штатный `systemctl daemon-reload` и
   `systemctl --user daemon-reload`, где применимо. Сам reload службы не
   перезапускает.
3. Проверить `NeedDaemonReload=no`, затем до обновления по одной перезапустить
   и проверить каждую custom-службу.
4. Остановить VPN и убедиться, что активные туннели отсутствуют.
5. Убедиться, что обычный интернет и DNS работают без VPN.
6. Выполнять release upgrade без TUN и изменённых маршрутов.

После обновления запускать Amnezia, Outline и Happ по одному, каждый раз
проверяя статус daemon, фактическое создание туннеля, DNS, default route,
reconnect и suspend/resume. Umbrella unit OpenVPN проверять только если он
реально используется; тестировать нужно конкретный профиль, а не
`active (exited)`.

Для Outline отдельно проверить наличие `libfuse2t64`, запуск обоих AppImage,
controller и autostart клиента. Для Tuna проверить запуск, чтение
`~/.config/tuna/tuna.yml` и соединение независимо от Happ.

## 12. Dual boot, EFI, GRUB и firmware

### Положительное

- EFI-раздел большой и почти пустой.
- Ubuntu Boot Manager — первая запись.
- Windows Boot Manager присутствует отдельной записью.
- Корень и EFI исправны по доступным read-only-проверкам.
- Корень сейчас не зашифрован. Новая TPM-backed FDE относится прежде всего к
  новой установке и не преобразует существующий ext4 автоматически при
  обычном in-place upgrade.

### Риски

- Ubuntu и Windows используют общий EFI-раздел.
- GRUB скрыт и имеет timeout 0.
- Второй NVMe содержит Windows/NTFS.
- Полный SMART/NVMe self-test без root-пароля не выполнялся.
- BIOS Acer обновлён с V1.21 до V1.26, но отдельные ACPI `I2C5` warnings
  сохранились.
- Ожидает high-priority UEFI dbx update до версии 20260402.

### Подготовка

- Сохранить Windows/BitLocker recovery key, если BitLocker включён.
- Создать recovery USB.
- Проверить F12 boot menu.
- Подготовить видимый GRUB и загрузку известного рабочего ядра.
- Проверить SMART/NVMe health обоих SSD. Минимальный критерий: нет critical
  warning, media/data-integrity errors и ошибок self-test; журнал без
  NVMe/EXT4 I/O errors, успешные `e2scrub` и `fstrim` являются хорошими
  сигналами, но не заменяют SMART.
- Не обновлять BIOS/dbx в то же maintenance window, что и Ubuntu.
- Firmware/dbx устанавливать отдельной операцией и отдельно проверять reboot.

  packages или failed critical units.
- Обновление предлагается только через `--devel-release`.

## 17. Проверка после обновления

### Базовая ОС

```bash
lsb_release -a
uname -r
echo "$XDG_SESSION_TYPE"
systemctl --failed
systemctl --user --failed
dpkg --audit
```

Ожидается Ubuntu 26.04.x, `XDG_SESSION_TYPE=wayland`, отсутствие failed units
и пустой `dpkg --audit`.

### NVIDIA

```bash
nvidia-smi
dkms status
ubuntu-drivers devices
prime-select query
journalctl -b -k --no-pager \
  --grep='NVRM: Xid|API mismatch|Idling display engine|NvKmsKapiMemory'
```

Проверить, что NVIDIA-модуль загружен именно для результата `uname -r`, а не
только числится DKMS-модулем другого ядра. Проверить Ollama и NVIDIA Container
Toolkit отдельно.

### Мониторы

### Сеть, периферия и питание

- Ethernet и Wi‑Fi: подключение, DNS, скорость и reconnect;
- Bluetooth: обнаружение и повторное подключение устройства;
- динамики/наушники и микрофон;
- webcam;
- клавиатура, touchpad и fingerprint;
- каждый USB-A/USB-C порт;
- HDMI и USB-C DisplayPort по отдельности и вместе;

Для каждого теста критерий простой: устройство определяется, выполняет
реальную операцию и переживает повторное подключение либо reboot без новых
ошибок в журнале.

### Удалённый рабочий стол

`gnome-remote-desktop.service` сейчас активен. Если RDP используется, сохранить
его настройки и проверить подключение, разрешение и масштабирование в
Wayland-сессии. Если удалённый доступ не используется, отметить службу как
несущественную для GO и не считать её простой активностью доказательством
проблемы.

- проверить `.trackerignore`;
- дождаться завершения индексации;
- проверить CPU/RAM miner;
- десять раз открыть ранее медленную папку;
- проверить файловые диалоги.

### Dual boot

- проверить GRUB;
- проверить старое рабочее ядро;
- проверить Windows Boot Manager через F12;
- не удалять recovery USB до завершения всех тестов.

## 18. Карта проблем, решений и проверки результата

| Проблема | Статус сейчас | Решение | Как понять, что решено |
| --- | --- | --- | --- |
| Штатный переход 24.04 → 26.04 закрыт | **Не решено; стоп-фактор** | Ждать 26.04.1 и открытия Canonical gate | `Supported: 1`, а `do-release-upgrade -c` без `-d` предлагает 26.04 |
| Нет проверенной backup/отката | **Не решено; стоп-фактор** | Внешняя зашифрованная backup, логические dumps и recovery USB/образ | Случайные файлы и базы реально восстановлены в отдельное место |
| Текущая схема мониторов зависит от X11 | **Не решено; высокий риск** | Отключить старый autostart, проверить Wayland 24.04 и GNOME 50 на клоне, настроить layout средствами GNOME | BenQ 200%, AOC 100%, eDP off сохраняются после двух relogin, двух reboot, hot-plug и sleep/wake |
| USB-C/DP иногда гаснет | **Не подтверждено исправленным** | A/B-тест другого сертифицированного кабеля, каждого порта и монитора; сопоставить blackout с kernel journal | 24–48 часов без blackout и без совпавших Xid/UCSI/NvKmsKapiMemory событий либо известен надёжный аппаратный workaround |
| Recovery kernel без NVIDIA-модуля | **Не решено** | Собрать/проверить NVIDIA для запасного ядра или проверить iGPU/nouveau/text fallback и GRUB | После фактической тестовой загрузки доступна графика или рабочая TTY/recovery |
| SMART обоих SSD не проверен | **Не проверено** | Выполнить SMART/NVMe health и self-test до maintenance window | Нет critical warning, media/data-integrity и self-test ошибок |
| APT/dpkg | **По кэшу исправно; свежая проверка ожидается** | `apt update` без ошибок, штатный `full-upgrade`, audit/holds/failed-units, reboot | Ноль GPG/404/source errors, broken/held packages и failed critical units |
| Docker data | **Backup не подтверждена** | Классифицировать volumes; сделать согласованные PostgreSQL/MinIO/Weaviate/application backups | Restore-test успешен; после `compose up -d` совпадают mounts и проходят SQL/object/readiness tests |
| Pipx и project venv на Python 3.12 | **Потребует миграции** | Сохранить списки/lock-файлы и пересоздать окружения на Python 3.14 | Pipx tools, systemd services и тесты проектов проходят |
| 12 внешних APT-источников и 3 local DEB | **Потребует проверки** | Включать поддерживаемые sources по одному; сохранить DEB и настройки | После каждого source чистый `apt update`, корректный origin/candidate и приложение запускается |
| VPN/custom units | **Есть `NeedDaemonReload`; миграция не проверена** | Сохранить units, daemon-reload, проверять и перезапускать продукты по одному | `NeedDaemonReload=no`; каждый нужный туннель, DNS, route и reconnect работают |
| Tracker/Nautilus | **Стабилизировано на 24.04; 26.04 не проверено** | Сохранить `.trackerignore`, проверить LocalSearch 3.11 и файловые диалоги | Нет extractor crash-loop; индексация завершается; папка открывается 10 раз без зависания |
| Dual boot/EFI/dbx | **Загрузка работает; dbx ожидает отдельно** | Сохранить BitLocker key, проверить F12/Windows; dbx обновлять в другое окно | Ubuntu, recovery kernel и Windows реально загружаются; отдельный dbx reboot успешен |
| Остальная периферия | **26.04 не проверена** | Выполнить полный hardware smoke-test из раздела 17 | Каждое устройство выполняет реальную операцию и переживает reconnect/reboot без новых ошибок |

## 19. Ограничения аудита

- `apt update` не запускался, чтобы не менять локальный APT-кэш. Доступный кэш
  обновлялся 25–26 июля и показывал 0 обычных ожидающих обновлений.
- Нельзя получить точный список удаляемых/заменяемых пакетов Resolute:
  официальный release upgrader ещё закрыт. Такой список нужно повторно
  проверить после `Supported: 1`.
- Wayland-сессия, новый Mutter, hot-plug и suspend/resume фактически не
  тестировались, потому что это потребовало бы изменения GDM и перезапуска
  пользовательского сеанса.
- Полные SMART/NVMe self-tests и часть root-only-проверок не выполнялись без
  пароля администратора. Доступные журнал, ext4 и UDisks-показатели чистые.
- Резервная копия и восстановление не проверялись, поскольку backup пока не
  настроен.
- Количество контейнеров, размер Docker cache, свободная память и нагрузка
  являются моментальными снимками и могут измениться.
- Наличие endpoint `resolute` проверено только для части сторонних
  репозиториев; это не заменяет официальную поддержку конкретного пакета
  поставщиком.
- Launchpad bugs приведены как похожие открытые сигналы, а не как доказательство
  неизбежного сбоя этого ноутбука.

## 21. Итог

Аппаратных ресурсов и свободного места достаточно; по доступным read-only
проверкам dpkg и локальный APT-кэш согласованы, но свежий `apt update` ещё
обязателен. Точная NVIDIA 595.84 доступна в Ubuntu 26.04, а основная версия
ядра уже совпадает. Поэтому обновление в принципе возможно.

Но **на 2026-07-26 ноутбук не готов к безопасному обновлению**:

- официальный LTS-переход ещё закрыт;
- backup не настроен;
- текущая схема дисплеев X11-специфична;
- GNOME 26.04 требует Wayland;
- USB-C/DP остаётся отдельной незакрытой проблемой;
- Docker, Python/Pipx, VPN и сторонние репозитории требуют подготовки.

Рекомендуемое решение: остаться на Ubuntu 24.04, выполнить резервное
копирование и Wayland/USB-C-тесты, дождаться Ubuntu 26.04.1 и `Supported: 1`,
затем повторить этот аудит. При успешных проверках обновление можно проводить
в подготовленное maintenance window с recovery USB и сохранённым старым
ядром.
