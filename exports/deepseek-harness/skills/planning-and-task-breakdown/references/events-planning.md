# Events Planning Artifacts

Read only when the confirmed manifest marks `events` active. Create only
manifest-listed files as repository-local planning artifacts.

Use AsyncAPI for an event contract when it fits repository protocols; otherwise
use the repository's native event schema. Map channels and messages to stable
requirement IDs, producers, consumers, identity, correlation, delivery,
ordering, deduplication, retry, dead-letter, replay, compatibility, and planned
provider/consumer checks. Keep semantics the format cannot express in one
referenced deterministic source rather than duplicating them in prose.

## Platform Applicability

Use agreed platform support to plan material producer/consumer checks across
environments and protocol versions, including broker compatibility where relevant.
Test required combinations against the shared requirement IDs.
