# Cross-Surface Planning Artifacts

Read only when the confirmed manifest marks `cross-surface` active. Create only
manifest-listed files as repository-local planning artifacts.

Map each UI action through its operation or event, domain state change,
success or failure, and resulting UI state with stable requirement IDs. Use the
smallest useful C4 context or container view and a dynamic view for material
runtime paths. Keep a text architecture model authoritative and rendered views
derived. Create an ADR only for a consequential cross-boundary choice with real
alternatives. Plan one end-to-end check for each material normal, failure, retry,
and recovery path.

## Platform Applicability

Use agreed platform support to plan material cross-platform end-to-end checks
for the required component combinations. Trace each observable outcome to shared
requirement IDs without expanding support or requiring every combination.
